# Historical migration: v0.7.5

This migration separated public handler access from internal routing and response-writer control, added role-aware DI validation and execution-store cleanup, and refined optional runtime descriptions.

The current source has since separated transport contexts. HTTP uses `spine.Ctx`; WS uses `spine.WebSocketCtx` or `context.Context`; event consumers use `spine.EventCtx`. Do not reintroduce the former common context's `WebSocket()` accessor.

HTTP obtains standard context and shared values through `ExecutionContext()`, request data through `HTTPRequestContext()` and output through `HTTPResponseContext()`. Retained views lose values and HTTP access after completion. Do not use internal routing setters or writer replacement in application code.

The old package-level event publisher was also superseded. Inject `publish.Publisher` and handle synchronous send errors. See [DI publishing](app-publisher.md), [WS migration](websocket-dx.md), [current source changes](v0.7.6.md) and the [Korean original](../ko/migration/v0.7.5.md).
