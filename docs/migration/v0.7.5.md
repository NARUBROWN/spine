# v0.7.5 프리뷰 API 전환

`v0.7.5-preview.1`은 내부 실행 계약과 개발자용 API를 분리하는 소스 후보입니다. 기존 내부 API 접근과 인터셉터 시그니처의 호환성을 끊으므로 아래 전환이 필요합니다. 현재 로컬 준비 버전이며 태그 발행이나 정식 승격을 완료한 상태가 아닙니다.

HTTP 입력은 계속 `input.Body[T]`, `input.Path[T]`, `input.Query[T]`와 `input.Header[T]`를 사용합니다. 이전 입력 변경은 [v0.7.2 안내](v0.7.2.md)를 참고하세요. 컨트롤러 등록과 핸들러의 `spine.Ctx` 인자 형태는 유지합니다.

## 핸들러와 인터셉터의 공통 컨텍스트

HTTP, 이벤트, WebSocket 핸들러와 인터셉터의 컨텍스트 인자로 `github.com/NARUBROWN/spine/pkg/spine`의 `Ctx`를 사용하세요. 기존 `core.ControllerContext` 인자는 `spine.Ctx`로 바꾸세요.

- 인터셉터와 핸들러는 `ctx.ExecutionContext().Set("userID", value)`로 값을 저장하고 `ctx.ExecutionContext().Get("userID")`로 읽습니다. 같은 실행을 전달한 다른 컨트롤러도 이 저장소를 공유합니다. 다른 요청의 컨트롤러는 별도 저장소를 사용합니다.
- 표준 Go 컨텍스트는 `ctx.ExecutionContext().Context()`로 가져옵니다. 이 값을 DB 호출, `publish.Event`, `ws.Send`에 넘길 수 있습니다.

공개 컨텍스트는 다음 인터페이스를 제공합니다. 내부 라우팅, 응답 writer 교체와 이벤트 큐 제어는 노출하지 않습니다.

```go
type ContextCarrier interface {
    Context() context.Context
}

type ExecutionContextView interface {
    ContextCarrier
    Get(key string) (any, bool)
    Set(key string, value any)
}

type Ctx interface {
    ExecutionContext() ExecutionContextView
    HTTPRequestContext() (HTTPRequestView, bool)
    HTTPResponseContext() (HTTPResponseView, bool)
    WebSocket() (WebSocketView, bool)
    // Deprecated: ExecutionContext().Get을 사용하세요.
    Get(key string) (any, bool)
}
```

HTTP 요청과 응답은 각각 조회합니다. 두 뷰는 같은 내부 요청 객체를 참조하며 별도 생명주기를 만들지 않습니다.

```go
request, requestOK := ctx.HTTPRequestContext()
response, responseOK := ctx.HTTPResponseContext()
if requestOK && responseOK {
    requestID := request.Header("X-Request-ID")
    response.SetHeader("X-Request-ID", requestID)
}
```

`HTTPRequestView`는 `Context()`, `Method()`, `Path()`, `Param()`, `Params()`, `PathKeys()`, `Query()`, `Queries()`, `Header()`, `Headers()`와 `MultipartForm()`을 제공합니다. 내부 입력 리졸버의 `Bind()`는 공개하지 않습니다. 멀티파트 필드와 파일 헤더는 사본을 반환하며, 파일 내용은 현재 요청에서만 사용합니다.

`HTTPResponseView`는 `SetHeader`, `AddHeader`, `IsCommitted`, `WriteStatus`, `WriteJSON`, `WriteString`과 `WriteBytes`를 제공합니다. 응답 뷰는 실행 중 현재 writer를 사용하므로 staging writer 교체를 따라갑니다. 요청이 끝난 뒤 보관한 뷰에서 헤더를 변경하면 반영되지 않고, 쓰기 메서드는 오류를 반환합니다. writer 자체를 꺼내거나 교체하는 메서드는 제공하지 않습니다. 일반 핸들러의 응답은 계속 `httpx.Response[T]` 같은 반환값으로 표현합니다.

각 getter는 해당 계약을 지원하지 않으면 `nil, false`를 반환합니다. 응답 getter는 현재 writer가 없을 때도 `nil, false`를 반환합니다. 요청 조회에 응답 계약을 요구하지 않습니다. 이번 로컬 후보의 이전 `ctx.HTTP().Request()`와 `ctx.HTTP().Response()`는 새 getter로 전환하며 호환 별칭은 제공하지 않습니다.

WebSocket의 handshake와 메시지는 `ctx.WebSocket()`으로 요청 정보를 조회합니다. 메시지에서는 `ConnID()`, `MessageType()`, `Payload()`도 사용할 수 있습니다. `Payload()`는 사본입니다. upgrade 전에는 연결 ID는 빈 문자열, 메시지 유형은 0, 페이로드는 nil입니다. handshake 인터셉터끼리는 저장소를 공유하지만 handshake가 반환되면 해제하며, 이후 메시지에는 각기 새 저장소를 만듭니다.

HTTP 실행은 HTTP 요청 및 응답 뷰를 제공하고, WebSocket handshake와 메시지는 `WebSocket()`을 제공합니다. 이벤트 실행은 모든 전송별 조회에서 `nil, false`를 반환합니다. 이벤트 이름과 DTO는 기존 핸들러 인자로 받습니다.

기존 `ctx.Get(key)`와 핸들러의 `context.Context` 직접 주입은 폐기 예정 경로이며 전환 기간에는 동작합니다. `spine.Ctx`를 직접 구현한 테스트 더블에는 `ExecutionContext()`, `HTTPRequestContext()`, `HTTPResponseContext()`와 `WebSocket()`이 필요합니다. 전송 뷰를 지원하지 않는 더블은 해당 메서드에서 `nil, false`를 반환하세요.

컨트롤러의 `RegisterRoutes(*api.Registry)`와 기존 `spine.Ctx` 핸들러 시그니처는 유지합니다. 인터셉터 네 메서드와 `PreHandshake`의 컨텍스트 인자는 `spine.Ctx`로 바꿔야 합니다. 이 변경은 이전 인터셉터 구현과 소스 호환성을 끊습니다.

## 실행별 저장소의 수명

`ExecutionContext().Set`으로 보관한 값은 같은 실행의 핸들러와 완료 훅에서 읽습니다. `AfterCompletion`까지 끝나고 실행이 반환되면 Spine이 저장값의 참조를 해제합니다. 성공, 오류 반환과 패닉 경로에 같은 규칙을 적용합니다.

앱이 컨텍스트 뷰를 보관해도 종료된 저장소의 `Get`은 `nil, false`를 반환하고 `Set`은 새 값을 보관하지 않습니다. 앱이 값 자체를 다른 곳에 저장했다면 그 참조의 수명은 앱이 관리합니다. 실제 메모리 회수 시점은 Go GC가 결정합니다.

저장소는 HTTP 요청, 이벤트 메시지와 WebSocket 메시지마다 별도이며 읽기와 쓰기, 종료를 동기화합니다. 이 수명은 표준 Go 컨텍스트의 취소 시점과 별개입니다. WebSocket 연결과 이벤트 소비 런타임의 표준 컨텍스트는 메시지 처리가 끝난 뒤에도 계속 살아 있을 수 있습니다.

## 기존 전체 파일 조회 API 폐기 예정

Spine의 `pkg/multipart.UploadedFile`과 `UploadedFiles`를 Deprecated로 표시합니다. 새 코드에서는 `input.Body[T]`의 폼 파일 필드를 사용하세요. 기존 핸들러의 실행은 유지합니다.

임의의 필드 이름으로 전송된 모든 파일을 조회하던 기능은 고정된 DTO 필드와 범위가 다릅니다. 이 기능이 필요하면 `request, ok := ctx.HTTPRequestContext()`로 요청 뷰를 얻고 `ok`를 확인한 뒤 `request.MultipartForm()`으로 받은 `spine.MultipartFields.File`을 조회하세요. 필드 목록은 사본이며 임시 파일은 Spine이 정리합니다. 폼과 파일은 현재 요청에서만 사용하세요.

## 내부 API 접근 종료

`v0.7.1`과 이전 `v0.7.2` 후보에서 아래 내부 API를 직접 사용했다면 업그레이드할 때 코드를 바꿔야 합니다. 인터셉터 컨텍스트는 위의 공통 `spine.Ctx`로 전환합니다.

| 이전 코드 | 전환 방법 |
| --- | --- |
| `core.ExecutionContext.SetRoute()` | HTTP 경로 파라미터는 `ctx.HTTPRequestContext()`로 받은 요청 뷰의 `Params()`로 조회하고, 공유 데이터는 `ctx.ExecutionContext().Set()`으로 저장합니다. 라우팅 전 HTTP 요청 경로를 바꿔야 한다면 `spine.NetHTTPHandler`를 감싸는 `net/http` 미들웨어에서 처리합니다. |
| `ctx.EventBus()`, `core.EventBus`, `core.EventBusCarrier` | 인터셉터의 `PreHandle`에서 `publish.Event(ctx.ExecutionContext().Context(), event)`를 호출합니다. 실행이 성공하면 디스패치가 `PostHandle` 전에 이 이벤트를 발행합니다. 브로커 발행 관찰은 `spine.WithEventAdapter`를, 핸들러 단위 테스트는 `publish.WithPublisher`를 사용합니다. 큐 소비는 프레임워크가 담당합니다. |
| `core.HTTPResponseContext.SetResponseWriter()` | 응답 헤더나 상태를 설정할 때는 `ctx.HTTPResponseContext()`로 받은 응답 뷰를 사용합니다. 전송 writer를 감싸야 한다면 `spine.NetHTTPHandler` 바깥에서 `net/http` 미들웨어를 적용합니다. |
| `core.HandlerMeta.Method`, `Callback`, `Interceptors` | 메서드 이름은 `MethodName`, 핸들러 이름과 시그니처는 `HandlerName()`과 `FunctionType()`으로 조회합니다. 인터셉터 유형은 `InterceptorTypes`로 조회합니다. 이 목록과 `PathKeys`는 호출마다 전달되는 사본입니다. |
| `core.HttpRequestContext`, `core.HTTPRequest` | `ctx.HTTPRequestContext()`로 조회합니다. 핸들러의 본문 디코딩에는 `input.Body[T]`를 사용합니다. |
| `core.ConsumerRequestContext`, `core.WebSocketContext`, `core.WebSocketMessageContext`, `core.WebSocketHandshakeContext` | 컨슈머는 핸들러 인자로 이벤트 이름이나 DTO를 받습니다. WebSocket 핸들러와 인터셉터는 `ctx.WebSocket()`으로 조회합니다. `Payload()`는 사본을 반환합니다. 메시지 변환은 핸들러의 DTO 디코딩 또는 애플리케이션 로직에서 처리합니다. |
| `api.Option`을 함수로 실행하거나 내부 라우트 필드를 직접 변경 | `api.Tags`, `api.Summary`, `api.Description`, `api.Interceptors`가 반환하는 옵션을 등록할 때 전달합니다. 조건부 옵션은 해당 조건을 만족할 때만 추가합니다. |
| `constructor.Registration.Role()`과 `Value()` | `constructor.Controller` 등 역할 팩터리의 반환값을 `app.Constructor`로 넘깁니다. 앱이 직접 만든 등록 목록을 검사해야 한다면 앱이 보유한 역할과 생성자를 조회합니다. |
| `httperr.InputError`, `boot.IsOpenAPIResourcePath` | 인터셉터에서 오류의 입력 출처는 `httperr.InputLocation(err)`로 조회합니다. 앱이 반환하는 입력 오류는 `httperr.BadRequest`로 표현합니다. OpenAPI 리소스 경로의 검증은 `app.Validate`로 확인합니다. |

`publish.DomainEvent`, `publish.EventPublisher`, `httperr.HTTPError`, `jsonx.NullError`와 `constructor.Registration`은 공개 이름으로 계속 사용할 수 있습니다. 이 타입들을 리플렉션으로 검사하는 도구는 선언 패키지 경로에 의존하는지 확인하세요. 실제 구현의 선언 위치는 내부 패키지로 이동했습니다.

## 부트 설정 검증의 공개 경로

설정 검증과 OpenAPI 기본 경로 계산은 `internal/configuration`으로 이동합니다. 내부 엔진은 이 구현을 직접 사용하며 앱이 내부 패키지를 가져오는 방식은 지원하지 않습니다.

다음 공개 보조 API는 호환성을 끊고 제거합니다. 앱 전체의 등록, 어댑터와 설정을 함께 확인하려면 `app.Validate(options)`를 사용하세요. 실제 생성자와 자원 준비까지 확인할 때는 `app.Prepare(ctx, options)`를 사용하고 성공한 결과를 `Close`하세요.

- `HTTPOptions.Validate`, `WebSocketOptions.Validate`와 각 설정의 `ValidateIssues`
- `OpenAPIOptions.DocumentPath`
- `boot.ValidationError`, `boot.MergeConfigIssues`와 `ConfigError.Append`

`boot.Options`, HTTP, WebSocket과 이벤트 설정 타입 및 공개 상수는 유지합니다. OpenAPI의 빈 `Path`는 계속 `/openapi.json`을 의미합니다. `boot.ConfigError`와 `ConfigIssue`도 유지하므로 호출자는 기존처럼 `errors.As`로 문제 목록을 조회할 수 있습니다.

```go
if err := app.Validate(options); err != nil {
    var configError *boot.ConfigError
    if errors.As(err, &configError) {
        for _, issue := range configError.Issues {
            log.Printf("%s [%s]: %s", issue.Path, issue.Code, issue.Message)
        }
    }
    return err
}
```

설정 타입과 오류 타입은 공개 별칭으로 유지하지만 실제 선언 위치는 내부 패키지로 바뀝니다. 선언 패키지 경로를 비교하는 리플렉션 코드는 공개 타입 자체의 동일성을 기준으로 바꾸세요.

## 문자열 응답의 타입 제한

`type Text string`처럼 새로 정의한 문자열 타입을 `httpx.Response[Text]` 또는 그 포인터로 반환하면 준비 단계에서 `HTTP_RETURN_UNSUPPORTED`로 거부합니다. 이전에는 실행과 OpenAPI의 지원 판정이 달라 요청 중 500이 발생했습니다. 새 코드에서는 본문을 `string(value)`로 바꾸고 `httpx.Response[string]`을 반환하세요.

일반 `string`, `type Text = string` 타입 별칭과 struct DTO 응답은 계속 지원합니다. 이 제한은 사용자 정의 타입 전체를 금지하는 규칙이 아닙니다.

## 등록 조회와 발행 및 송신

| 이전 내부 접근 | 공개 전환 경로 |
| --- | --- |
| `api.Registry.Freeze()` | 직접 호출을 제거합니다. 앱 준비 과정에서 프레임워크가 등록을 마감합니다. |
| `Consumers().Registrations()`, `WebSocket().Registrations()` 또는 `Snapshot()` | `spine.DescribeRegistrations(app)`로 등록 정보의 사본을 조회합니다. |
| `ws.SenderKey` | 메시지 핸들러의 `ctx.ExecutionContext().Context()`를 `ws.Send`에 전달합니다. |
| `publish.PublisherKey` | 핸들러 단위 테스트는 `publish.WithPublisher`를 사용합니다. 브로커 통합과 가짜 어댑터 테스트는 `spine.WithEventAdapter`를 사용합니다. |

객체를 직접 넘기는 `app.Constructor(&T{})`, `App.Route`와 `route.WithInterceptors`는 폐기 예정입니다. 생성자 함수나 역할 표식을 사용하고, 신규 라우트는 컨트롤러의 `RegisterRoutes(*api.Registry)`와 `api.Interceptors`로 등록하세요.
