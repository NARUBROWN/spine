# Spine v0.7.0 전환

이 소스의 정식 대상 버전은 v0.7.0입니다. Preview, RC, 정식 공개 상태는 태그와 검증 기록으로 확인하세요. [릴리스 운영](../../RELEASING.md)에 채널별 발행 순서와 검증 범위를 설명합니다.

## HTTP 입력과 명세

본문, 경로, 쿼리와 헤더는 출처별 구조체 포인터로 받습니다. 기존 query.Values, header.Values, query.Pagination과 path 래퍼는 Deprecated이며 새 출처 DTO와 한 핸들러에서 혼용할 수 없습니다. 일반 값 타입에 명시적인 JSON null을 전달하면 입력 오류로 거부합니다.

HTTP 계약은 `spine.http-adapter/v3`이며 본문은 공통 파서가 해석합니다. 이 소스의 Preview 코어 후보는 `v0.7.0-preview.13`이며, 공개 조합은 Echo `v0.2.0-preview.4`와 net/http `v0.1.0-preview.2`를 검증 대상으로 고정합니다. 공개 발행과 전체 조합 완료 여부는 [릴리스 운영](../../RELEASING.md#정책과-소스-ci)에서 확인하세요. HTTP v2 플랫폼은 그대로 연결할 수 없습니다. CLI `v0.4.3-preview.4`부터 두 플랫폼의 생성, 계약 분석과 업데이트를 지원합니다. [HTTP v3 전환](http-v3.md)에서 입력 처리와 Prepared API 변경을 확인하세요.

런타임 OpenAPI는 기본 비활성화입니다. `OpenAPI: boot.OpenAPIOptions{Enabled: true}`로 활성화하며, 경로를 생략하면 `/openapi.json`을 사용합니다. 기존 작업 소스의 Disabled 필드는 Enabled로 변경되었습니다.

상세 코드 예와 오류 정책은 [구조체 입력 전환](structured-inputs.md)을 참고하세요. Swagger UI와 ReDoc은 선택적으로 활성화할 수 있습니다. CLI는 `contract export --format openapi --source runtime`으로 런타임 명세를 내보냅니다. 정적 OpenAPI의 입력 표현 문제는 [spine-cli#34](https://github.com/NARUBROWN/spine-cli/issues/34)에서 별도로 추적합니다.

## 컨트롤러와 생성자 등록

전역 인터셉터가 빈 `HandlerMeta`의 이름을 조회할 때 패닉을 내지 않습니다. `constructor.Custom`으로 등록한 팩토리는 반환 인터페이스가 `api.Controller`를 포함해도 HTTP 수집 후보에서 제외하며, 추상 컨트롤러 오류로 거부하지 않습니다.

`v0.7.0-preview.7` 후보는 컨트롤러의 `RegisterRoutes(*api.Registry)` 안에 경로와 콜백을 선언합니다. `input.Path[T]`, `input.Query[T]`, `input.Body[T]`는 입력 출처를 표시하고 DTO 필드에 직접 접근할 수 있습니다.

`v0.7.0-preview.10`부터 `Registry`와 `Group`의 HTTP 라우트 호출은 모두 `path, handler, options...` 순서를 사용합니다. `api.OptionSet`과 `api.Options`는 제거되며 `api.Tags`, `api.Summary`, `api.Description`, `api.Interceptors`를 핸들러 뒤에 직접 전달합니다. `v0.7.0-preview.9`까지의 그룹 호출과 호환되지 않으므로 코어와 CLI 후보를 함께 갱신합니다.

`v0.7.0-preview.7`부터 `app.Route`와 기존 컨트롤러 정의 방식을 Deprecated로 표시합니다. 전환 기간에는 기존 등록과 새 등록을 한 앱에서 함께 사용할 수 있습니다. [기존 컨트롤러 전환 절차](controller-routes.md#기존-컨트롤러-전환)를 참고하세요.

앱은 `app.Constructor(...)` 안에서 `constructor.Custom`, `Repository`, `Service`, `Controller`, `Interceptor`로 역할을 표시합니다. 객체의 생성 메서드는 `Constructor(의존성...) *자기타입`이며, `Custom`은 기존 생성자 함수도 지원합니다. 공통 생성 계약과 추가 역할 계약, 의존성 그래프를 생성자 실행 전에 검사합니다. 인터셉터 적용 범위는 별도로 지정합니다.

CLI의 대응 후보는 `v0.4.3-preview.8`, 요청별 검증 오류 이름을 지원하는 playground 후보는 `v0.2.0-preview.6`입니다. 공개 발행 전에는 짝이 맞는 소스 조합으로 검증하며, 이 안내가 태그나 원격 CI의 완료를 뜻하지 않습니다. 코어의 최소 Go 버전은 1.25.5로 유지합니다.

[컨트롤러 작성과 명세 경계](controller-routes.md), [역할별 생성자 등록](component-contracts.md)에서 전환 방법을 확인하세요. 준비 전 런타임 명세 조회는 `ErrRoutesNotCollected`를 반환하며, CLI가 `Prepare`나 DB 연결을 자동 실행하지 않습니다. 기존 코드와 DTO는 CLI 정적 export로 검사할 수 있습니다.

## 관리 서버의 TLS

`boot.HTTPOptions.TLS`에 인증서를 담은 `*tls.Config`를 지정하면 관리 서버를 HTTPS로 실행합니다. nil이면 기존 평문 HTTP를 사용합니다. 준비한 설정은 `HTTPAdapter.Serve(listener)`의 기본값이며 실행 시 `httpcontract.WithTLS(config)`로 교체할 수 있습니다. 공개 실행 진입점은 `Serve` 하나입니다.

플랫폼 구현체의 시그니처는 `Serve(net.Listener, ...httpcontract.ServeOption) error`로 바뀝니다. 정적 인증서 오류와 미지원 기능은 native 초기화 전에 검사하며, 인증서 선택 콜백은 실제 연결에서 호출합니다. 외부 서버에 handler만 연결하는 경우 TLS 실행은 외부 서버 소유입니다. [TLS 설정 예시](http-v3.md#관리-서버의-tls)에서 인증서 로드와 소유권을 확인하세요.

이 변경은 HTTP 버전 선택과 ALPN 정책을 추가하지 않습니다. HTTP/2와 HTTP 스펙 개선은 별도 이슈에서 검토합니다.

## 플랫폼 채널

Echo, net/http, Gorilla, Kafka, RabbitMQ, NATS와 playground는 독립적인 버전과 태그를 사용합니다. 플랫폼은 공개 계약을 사용하는 데 필요한 코어 의존성을 유지하며, 코어 릴리스는 기존 플랫폼 태그를 재사용할 수 있습니다. 코어 후보 태그와 선택한 공개 플랫폼 모듈을 함께 설치해 전체 조합을 검증합니다. 코어 후보 태그만 있는 상태는 승격 가능한 조합이 아닙니다.

## 기존 경로와 예제

wsadapter를 adapter/websocket으로 옮긴 변경은 [기존 경로 전환 안내](v0.6.6.md)를 참고하세요. 기존 정식 예제 앱은 정식 태그 고정을 유지하며 코어와 플랫폼의 정식 발행 후 갱신합니다. 예제 갱신을 후보 발행의 선행 조건으로 사용하지 않습니다.
