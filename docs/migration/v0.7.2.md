# v0.7.2 핫픽스 전환

`v0.7.2-preview.2`은 누락된 `input.Header[T]`를 추가하는 프리뷰입니다. 래퍼 없는 HTTP 구조체 포인터 입력은 제거합니다. `input.Path[PathDTO]`는 계속 지원합니다. 정식 릴리스까지 완료한 버전은 아닙니다.

## 래퍼 없는 HTTP 입력 제거

HTTP 핸들러에서 `*BodyDTO`, `*QueryDTO`, `*HeaderDTO`, `*PathDTO`를 직접 받으면 준비 단계에서 `HTTP_INPUT_WRAPPER_REQUIRED`로 거부합니다. `input.Body[BodyDTO]`, `input.Query[QueryDTO]`, `input.Header[HeaderDTO]`, `input.Path[PathDTO]`로 바꾸세요. `json`, `form`, `header` 등의 태그는 필드 이름을 지정하는 용도로 유지합니다. 스칼라 경로 입력도 유지합니다. 이벤트와 WebSocket 페이로드 및 응답 DTO는 이 HTTP 입력 변경의 대상이 아닙니다.

`v0.7.2-preview.1`은 이 제거가 빠진 후보이므로 새 후보의 go.mod에서 retract로 표시합니다. 이번 변경은 새 핫픽스 PR이며 후보 태그 발행 완료를 뜻하지 않습니다.

## 헤더 입력 출처 선언

핸들러 인자에 `input.Header[T]`를 사용합니다. `header` 태그는 헤더 이름을 지정하고, 래퍼는 입력 출처를 지정합니다. 태그를 생략한 필드는 기존 타입 입력의 lowerCamel 기본 이름을 사용하며 헤더 이름은 대소문자를 구분하지 않습니다. 예를 들어 `RequestID`의 기본 이름은 `requestId`이며 `X-Request-ID`를 읽으려면 태그로 지정해야 합니다.

```go
import "github.com/NARUBROWN/spine/pkg/input"

type UserHeaders struct {
    RequestID string `header:"X-Request-ID" validate:"required"`
    Host      string `header:"Host"`
}

// 핸들러 인자: headers input.Header[UserHeaders]
```

기존 `*UserHeaders` 인자는 `input.Header[UserHeaders]`로 바꿔야 합니다. 새 래퍼는 기존 헤더 파서, 검증기와 OpenAPI 입력 계획을 공유합니다.

헤더 검증 오류의 `fields[].field`에는 표준화된 헤더 이름이 들어갑니다. 예를 들어 `X-Request-ID`는 `/X-Request-Id`로 표시됩니다. 기존 오류 응답의 필드 이름을 대소문자까지 비교하는 클라이언트는 이 표기에 맞춰 수정하세요.

## 본문과 파일 업로드

`input.Body[T]`는 JSON 전용이 아닙니다. 요청의 Content-Type에 따라 JSON, XML, URL-encoded form과 multipart를 처리합니다. JSON은 `json`, 폼과 multipart는 `form` 태그로 필드 이름을 지정합니다.

```go
import "mime/multipart"

type UploadBody struct {
    Title string                  `json:"title" form:"title"`
    Files []*multipart.FileHeader `json:"-" form:"files"`
}

// 핸들러 인자: body input.Body[UploadBody]
```

같은 `files` 필드로 보낸 여러 파일을 슬라이스로 받습니다. 파일은 요청 처리 중에 열고 닫아야 합니다. 완료 훅이 끝나면 임시 파일을 정리하므로 이후에도 사용할 파일은 별도로 저장하세요. 이 본문 파서 기능은 기존에 지원하던 기능이며 이번 패치에서 실제 HTTP 회귀 검사를 추가했습니다.

## 기존 전체 파일 조회 API 폐기 예정

Spine의 `pkg/multipart.UploadedFile`과 `UploadedFiles`를 Deprecated로 표시합니다. 새 코드에서는 `input.Body[T]`의 폼 파일 필드를 사용하세요. 기존 핸들러의 실행은 유지합니다.

임의의 필드 이름으로 전송된 모든 파일을 조회하던 기능은 고정된 DTO 필드와 범위가 다릅니다. 이 기능이 필요하면 HTTP 인터셉터에서 `ctx.(core.HTTPRequest)`로 요청 뷰를 얻고 `MultipartForm()`으로 받은 `core.MultipartFields.File`을 조회하세요. 필드 목록은 사본이며 임시 파일은 Spine이 정리합니다. 폼과 파일은 현재 요청에서만 사용하세요.

## 핸들러 컨텍스트

HTTP, 이벤트, WebSocket 핸들러의 컨텍스트 인자로 `github.com/NARUBROWN/spine/pkg/spine`의 `Ctx`를 사용하세요. 기존 `core.ControllerContext` 인자는 `spine.Ctx`로 바꾸세요.

- 인터셉터가 설정한 값은 `ctx.ExecutionContext().Get("userID")`로 읽습니다.
- 표준 Go 컨텍스트는 `ctx.ExecutionContext().Context()`로 가져옵니다. 이 값을 DB 호출, `publish.Event`, `ws.Send`에 넘길 수 있습니다.

기존 `ctx.Get(key)`와 핸들러의 `context.Context` 직접 주입은 폐기 예정 경로이며 전환 기간에는 동작합니다. `spine.Ctx`를 직접 구현한 테스트 더블에는 `ExecutionContext() spine.ExecutionContextView`를 추가하세요.

## 실행별 저장소의 수명

인터셉터의 `Set`으로 보관한 값은 같은 실행의 핸들러와 완료 훅에서 읽습니다. `AfterCompletion`까지 끝나고 실행이 반환되면 Spine이 저장값의 참조를 해제합니다. 성공, 오류 반환과 패닉 경로에 같은 규칙을 적용합니다.

앱이 컨텍스트 뷰를 보관해도 종료된 저장소의 `Get`은 `nil, false`를 반환하고 `Set`은 새 값을 보관하지 않습니다. 앱이 값 자체를 다른 곳에 저장했다면 그 참조의 수명은 앱이 관리합니다. 실제 메모리 회수 시점은 Go GC가 결정합니다.

저장소는 HTTP 요청, 이벤트 메시지와 WebSocket 메시지마다 별도이며 읽기와 쓰기, 종료를 동기화합니다. 이 수명은 표준 Go 컨텍스트의 취소 시점과 별개입니다. WebSocket 연결과 이벤트 소비 런타임의 표준 컨텍스트는 메시지 처리가 끝난 뒤에도 계속 살아 있을 수 있습니다.

## Preview의 내부 API 접근 종료

`v0.7.1`과 이전 `v0.7.2` 후보에서 아래 내부 API를 직접 사용했다면 업그레이드할 때 코드를 바꿔야 합니다. 인터셉터 네 메서드의 시그니처는 유지합니다.

| 이전 코드 | 전환 방법 |
| --- | --- |
| `core.ExecutionContext.SetRoute()` | 경로 파라미터는 `Params()`로 조회하고, 인터셉터가 핸들러에 전달할 데이터는 `Set()`으로 저장합니다. 라우팅 전 HTTP 요청 경로를 바꿔야 한다면 `spine.NetHTTPHandler`를 감싸는 `net/http` 미들웨어에서 처리합니다. |
| `ctx.EventBus()`, `core.EventBus`, `core.EventBusCarrier` | 인터셉터의 `PreHandle`에서 `publish.Event(ctx.Context(), event)`를 호출합니다. 실행이 성공하면 디스패치가 `PostHandle` 전에 이 이벤트를 발행합니다. 브로커 발행 관찰은 `spine.WithEventAdapter`를, 핸들러 단위 테스트는 `publish.WithPublisher`를 사용합니다. 큐 소비는 프레임워크가 담당합니다. |
| `core.HTTPResponseContext.SetResponseWriter()` | 응답 헤더나 상태를 설정할 때는 `ResponseWriter()`를 사용합니다. 전송 writer를 감싸야 한다면 `spine.NetHTTPHandler` 바깥에서 `net/http` 미들웨어를 적용합니다. |
| `core.HandlerMeta.Method`, `Callback`, `Interceptors` | 메서드 이름은 `MethodName`, 핸들러 이름과 시그니처는 `HandlerName()`과 `FunctionType()`으로 조회합니다. 인터셉터 유형은 `InterceptorTypes`로 조회합니다. 이 목록과 `PathKeys`는 호출마다 전달되는 사본입니다. |
| `core.HttpRequestContext` | HTTP 인터셉터에서 `core.HTTPRequest`로 조회합니다. 핸들러의 본문 디코딩에는 `input.Body[T]`를 사용합니다. |
| `core.ConsumerRequestContext`, `core.WebSocketContext` | 컨슈머는 핸들러 인자로 이벤트 이름이나 DTO를 받습니다. WebSocket 인터셉터는 `core.WebSocketMessageContext`로 조회합니다. `Payload()`는 사본을 반환합니다. 메시지 변환은 핸들러의 DTO 디코딩 또는 애플리케이션 로직에서 처리합니다. |
| `api.Option`을 함수로 실행하거나 내부 라우트 필드를 직접 변경 | `api.Tags`, `api.Summary`, `api.Description`, `api.Interceptors`가 반환하는 옵션을 등록할 때 전달합니다. 조건부 옵션은 해당 조건을 만족할 때만 추가합니다. |
| `constructor.Registration.Role()`과 `Value()` | `constructor.Controller` 등 역할 팩터리의 반환값을 `app.Constructor`로 넘깁니다. 앱이 직접 만든 등록 목록을 검사해야 한다면 앱이 보유한 역할과 생성자를 조회합니다. |
| `httperr.InputError`, `boot.IsOpenAPIResourcePath` | 인터셉터에서 오류의 입력 출처는 `httperr.InputSource(err)`로 조회합니다. 앱이 반환하는 입력 오류는 `httperr.BadRequest`로 표현합니다. OpenAPI 리소스 경로의 검증은 `app.Validate`로 확인합니다. |

`publish.DomainEvent`, `publish.EventPublisher`, `httperr.HTTPError`, `jsonx.NullError`와 `constructor.Registration`은 공개 이름으로 계속 사용할 수 있습니다. 이 타입들을 리플렉션으로 검사하는 도구는 선언 패키지 경로에 의존하는지 확인하세요. 실제 구현의 선언 위치는 내부 패키지로 이동했습니다.

## v0.7.1 철회 안내

`v0.7.1`은 `input.Header[T]`가 누락되어 철회 대상으로 지정합니다. 새 go.mod에 retract를 추가하지만, 더 높은 정식 버전이 아닌 프리뷰만 발행한 상태에서는 Go가 기존 정식 버전에서 철회 정보를 읽을 수 있습니다. 따라서 현재 패치는 `go get github.com/NARUBROWN/spine@v0.7.2-preview.2`처럼 명시적으로 선택하고, 자동 최신 버전 선택에 철회가 반영됐는지는 공개 모듈 조회로 확인해야 합니다. 기존 태그와 체크섬은 유지합니다.

CLI의 헤더 래퍼 검사와 Body 폼 OpenAPI 수정은 별도 CLI 릴리스에 포함되어야 합니다. 코어 태그 발행만으로 설치된 CLI가 갱신되지는 않습니다.
