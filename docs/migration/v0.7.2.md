# v0.7.2 핫픽스 전환

`v0.7.2-preview.2`은 누락된 `input.Header[T]`를 추가하는 프리뷰입니다. 래퍼 없는 HTTP 구조체 포인터 입력은 제거합니다. `input.Path[PathDTO]`는 계속 지원합니다. 정식 릴리스까지 완료한 버전은 아닙니다.

## 래퍼 없는 HTTP 입력 제거

HTTP 핸들러에서 `*BodyDTO`, `*QueryDTO`, `*HeaderDTO`, `*PathDTO`를 직접 받으면 준비 단계에서 `HTTP_INPUT_WRAPPER_REQUIRED`로 거부합니다. `input.Body[BodyDTO]`, `input.Query[QueryDTO]`, `input.Header[HeaderDTO]`, `input.Path[PathDTO]`로 바꾸세요. `json`, `form`, `header` 등의 태그는 필드 이름을 지정하는 용도로 유지합니다. 스칼라 경로 입력도 유지합니다. 이벤트와 WebSocket 페이로드 및 응답 DTO는 이 HTTP 입력 변경의 대상이 아닙니다.

`v0.7.2-preview.1`은 이 제거가 빠진 후보이므로 새 후보의 go.mod에서 retract로 표시합니다. 이번 변경은 새 핫픽스 PR이며 후보 태그 발행 완료를 뜻하지 않습니다.

## 헤더 입력 출처 선언

핸들러 인자에 `input.Header[T]`를 사용합니다. `header` 태그는 헤더 이름을 지정하고, 래퍼는 입력 출처를 지정합니다. 태그를 생략한 필드는 기존 타입 입력의 lowerCamel 기본 이름을 사용하며 헤더 이름은 대소문자를 구분하지 않습니다. 예를 들어 `RequestID`의 기본 이름은 `requestId`이며 `X-Request-ID`를 읽으려면 태그로 지정해야 합니다.

```go
import "github.com/NARUBROWN/spine/pkg/input"

type UserHeaders struct {
    RequestID string `header:"X-Request-ID" validate:"required"`
    Host      string `header:"Host"`
}

// 핸들러 인자: headers input.Header[UserHeaders]
```

기존 `*UserHeaders` 인자는 `input.Header[UserHeaders]`로 바꿔야 합니다. 새 래퍼는 기존 헤더 파서, 검증기와 OpenAPI 입력 계획을 공유합니다.

헤더 검증 오류의 `fields[].field`에는 표준화된 헤더 이름이 들어갑니다. 예를 들어 `X-Request-ID`는 `/X-Request-Id`로 표시됩니다. 기존 오류 응답의 필드 이름을 대소문자까지 비교하는 클라이언트는 이 표기에 맞춰 수정하세요.

## 본문과 파일 업로드

`input.Body[T]`는 JSON 전용이 아닙니다. 요청의 Content-Type에 따라 JSON, XML, URL-encoded form과 multipart를 처리합니다. JSON은 `json`, 폼과 multipart는 `form` 태그로 필드 이름을 지정합니다.

```go
import "mime/multipart"

type UploadBody struct {
    Title string                  `json:"title" form:"title"`
    Files []*multipart.FileHeader `json:"-" form:"files"`
}

// 핸들러 인자: body input.Body[UploadBody]
```

같은 `files` 필드로 보낸 여러 파일을 슬라이스로 받습니다. 파일은 요청 처리 중에 열고 닫아야 합니다. 완료 훅이 끝나면 임시 파일을 정리하므로 이후에도 사용할 파일은 별도로 저장하세요. 이 본문 파서 기능은 기존에 지원하던 기능이며 이번 패치에서 실제 HTTP 회귀 검사를 추가했습니다.

## 기존 전체 파일 조회 API 폐기 예정

Spine의 `pkg/multipart.UploadedFile`과 `UploadedFiles`를 Deprecated로 표시합니다. 새 코드에서는 `input.Body[T]`의 폼 파일 필드를 사용하세요. 기존 핸들러의 실행은 유지합니다.

임의의 필드 이름으로 전송된 모든 파일을 조회하던 기능은 고정된 DTO 필드와 범위가 다릅니다. 이 기능이 필요하면 실행 컨텍스트가 제공하는 `core.HttpRequestContext.MultipartForm()`에서 `Form.File`을 조회할 수 있습니다. `core.HttpRequestContext` 자체를 새 기본 핸들러 인자로 지원한다는 의미는 아닙니다.

## 핸들러 컨텍스트

핸들러가 인터셉터에서 설정한 값을 읽을 때는 `github.com/NARUBROWN/spine/pkg/spine`의 `Ctx`를 사용하세요. 기존 `core.ControllerContext` 인자는 `spine.Ctx`로 바꾸고 기존 `Get` 호출을 유지하세요. 타입 선언을 그대로 두면 새 코어에서 컴파일 오류가 납니다.

## v0.7.1 철회 안내

`v0.7.1`은 `input.Header[T]`가 누락되어 철회 대상으로 지정합니다. 새 go.mod에 retract를 추가하지만, 더 높은 정식 버전이 아닌 프리뷰만 발행한 상태에서는 Go가 기존 정식 버전에서 철회 정보를 읽을 수 있습니다. 따라서 현재 패치는 `go get github.com/NARUBROWN/spine@v0.7.2-preview.2`처럼 명시적으로 선택하고, 자동 최신 버전 선택에 철회가 반영됐는지는 공개 모듈 조회로 확인해야 합니다. 기존 태그와 체크섬은 유지합니다.

CLI의 헤더 래퍼 검사와 Body 폼 OpenAPI 수정은 별도 CLI 릴리스에 포함되어야 합니다. 코어 태그 발행만으로 설치된 CLI가 갱신되지는 않습니다.
