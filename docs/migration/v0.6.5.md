# Spine v0.6.5 전환

v0.6.5는 HTTP·WebSocket·이벤트·DTO 검증의 계약 분리와 App 연결을 한 릴리스로 제공합니다. 코어는 표준 라이브러리만 사용하고, 구체 구현은 외부 모듈에서 선택합니다.

| 계약 | 구현 |
| --- | --- |
| `contract/http` | `spine-echo-platform` |
| `contract/websocket` | `spine-gorilla-platform` |
| `contract/event` | `spine-kafka-platform`, `spine-rabbitmq-platform` |
| `contract/validator` | `spine-validator-playground` |

이전 `adapter`, `adapter/http`, `adapter/event`, `wsadapter`는 같은 타입과 오류의 호환 별칭입니다. 새 구현은 정식 `contract/` 경로를 사용합니다.

현재 main의 WebSocket 별칭 경로 변경은 [v0.6.6 전환 안내](v0.6.6.md)에 정리했습니다. 이미 배포된 v0.6.5 태그의 파일 구조는 변경하지 않습니다.

## App 조립

```go
factory, err := kafkaplatform.NewFactory(config)
if err != nil {
    return nil, boot.Options{}, err
}
validator, err := playground.New()
if err != nil {
    return nil, boot.Options{}, err
}
app := spine.New(
    echoplatform.Option(),
    gorillaplatform.Option(),
    spine.WithEventAdapter("events", factory),
    spine.WithValidator(validator),
)
```

위 생성식은 기존 `BuildApplication() (spine.App, boot.Options, error)` 안에서 사용합니다. 각 플랫폼 모듈을 표시한 별칭으로 import합니다. `Constructor`, `Route`, `Consumers().Register`, `WebSocket().Register`와 Echo의 `WithEcho` native 훅은 유지합니다.

HTTP만 사용하면 WS·event·validator 옵션을 생략합니다. WS 경로를 등록하면 HTTP의 업그레이드 지원과 별도의 WS factory가 모두 필요합니다. HTTP 없는 worker는 HTTP·WS 옵션과 `boot.Options.HTTP`를 생략합니다.

## 이벤트와 검증 변경

기존 `boot.Options.Kafka`, `boot.Options.RabbitMQ`와 broker 전용 boot 타입은 제거했습니다. broker 주소·자격 증명·native 설정은 외부 플랫폼의 `Config`에 넣습니다. 공통 재연결과 settlement 정책은 `WithEventAdapter` 옵션으로 지정합니다. 준비 과정에서 ready reader를 확보하고 같은 reader를 실행하며, 후처리 성공 뒤 ACK·실패 시 NACK합니다. Kafka의 실패 offset 보호와 RabbitMQ reject/requeue 정책은 각 구현 문서를 따릅니다.

`WithValidator`는 바인딩한 HTTP JSON·폼, WS·consumer DTO를 핸들러 전에 검증합니다. 생략하면 기존 바인딩만 수행합니다. 규칙 위반은 HTTP 400의 필드 오류, WS 1008 종료, consumer NACK 정책으로 연결합니다. 처리 오류·취소는 규칙 위반과 구분합니다. HTTP 필드 오류 경로는 JSON Pointer이며 거부한 입력값을 자동으로 노출하지 않습니다.

## 설치와 확인

코어와 일반 플랫폼은 Go 1.25.5 이상, 현재 playground 검증기는 Go 1.26 이상이 필요합니다. 새 프로젝트는 호환 버전을 고정하는 CLI 레시피로 생성합니다. 선택 옵션은 `spine schema --json`에서 확인합니다.

기존 프로젝트의 `spine update`는 의존성만 갱신하며 소스나 WS 선택을 자동 추가하지 않습니다. 먼저 생성식과 설정을 검토하고, dry-run의 diff·base_hash를 확인한 뒤 `--if-match`로 적용합니다. 이후 `contract check`, `verify`와 실제 HTTP·WS·브로커 검증을 별도로 수행합니다.

자세한 설명은 [이벤트 전환](event-platforms.md), [WS 전환](websocket-platforms.md), [검증 계약](../../contract/validator/README.md), [공개 플랫폼 E2E](../../test/platform-e2e/README.md)를 참고하세요.
